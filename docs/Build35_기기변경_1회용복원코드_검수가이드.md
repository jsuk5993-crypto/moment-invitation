# MOMENT Build 35 — 기기변경·브라우저 초기화 대비 구매 복원 (TEST 전용)

## 작동 방식
- 기존 구매자는 **기존 브라우저에서 구매 권한이 유효할 때** [1회용 복원코드 발급·재발급]을 눌러 64자리 보안 코드를 생성하고 별도로 저장합니다.
- 코드 원문은 발급 응답과 화면에 **한 번만** 표시하며 D1에는 SHA-256 해시만 저장합니다.
- 다른 기기의 비공개 TEST 제작기에서 코드를 입력하면 Worker가 해시로 주문을 찾아 **토스 결제 상태가 DONE인지 서버에서 확인**합니다.
- 성공 시 D1의 구매 토큰과 복원코드를 **하나의 D1 원자적 batch 트랜잭션**으로 교체하여 새 구매 권한과 **다음 사용용 새 1회용 복원코드**를 반환합니다.
- 사용된 복원코드와 기존 브라우저의 토큰은 폐기됩니다. **새 코드를 반드시 다시 보관**해야 합니다.
- 중복 사용, 임의 주문번호 입력, 미결제·환불, 토스 API 장애 시 권한을 부여하지 않습니다. 환불 시 관리자용 토스 재확인과 권한 회수가 유지됩니다.
- 신규 결제 정지(PAYMENTS_ACTIVE=false) 상태에서도 기존 구매자의 복원은 가능합니다. TEST 전용 스테이징 로그인은 그대로 강제합니다.
- 공개 main 브랜치와 실제 결제 모드는 변경하지 않습니다.

## 수동 검수
1. Cloudflare Worker와 정적 사이트가 같은 최신 개발 빌드인지 확인합니다. /api/payment-setup 에서 build=35 확인.
2. 이미 구매한 브라우저에서 프리미엄 이용 중인지 확인하고 [1회용 복원코드 발급·재발급]을 누릅니다.
3. 발급한 코드를 복사해 **테스트 용도**로 따로 보관합니다.
4. 시크릿 창 또는 다른 기기로 비공개 TEST에 로그인하고 '기존 구매 복원'에 코드를 붙여넣습니다.
5. 프리미엄 6종과 PNG 두 장의 다운로드 가능 여부, 새 코드 표시 여부를 확인합니다.
6. 이전 코드를 다시 입력하면 실패하는지, 원래 브라우저의 이전 구매 토큰이 무효인지 확인합니다.
7. 구매 이력이 있는 기존 브라우저에서도 [재발급]은 이전 코드를 무효화함을 확인합니다.
8. 구매 미완료·환불 상태 및 토스 장애 시 기존 구매권한이 새로 발급되지 않는지 검수합니다.

## 제품 및 운영 주의
- 이 방식은 이메일/회원 인증 없이 **고객이 직접 비밀 복원코드를 보관하는 방식**입니다. 브라우저 기록과 복원코드를 **둘 다 잃어버리면 자동 복원할 수 없습니다.**
- 복원코드 소지자는 구매 권한을 이전할 수 있습니다. 민감한 코드이므로 누구에게도 공유하거나 채팅으로 보내지 마세요.
- 코드 재사용을 막기 위해 복원 시 기존 브라우저의 구매 토큰은 무효화되며, 여러 기기에서 동시에 사용하려는 용도는 아닙니다.
- 복원 응답을 받은 뒤 브라우저가 중단되면 새 코드와 토큰을 모두 놓칠 수 있습니다. 운영 전에는 고객지원 및 별도 구매자 신원확인 기반 복구 절차가 필요합니다.
- 복원코드가 분실된 기존 유료 고객은 기존 기기에 접근할 수 있을 때만 재발급할 수 있습니다. 고객계정/이메일 인증 및 분실 복구는 후속 과제입니다.
- 초기 정식 판매 전에는 사업자 고지, 주문내역 전달, 문의처, 개인정보 및 법정 환불 요건도 별도 점검해야 합니다.

- 기기 복원 시 이전 결제 승인용 checkout_hash도 폐기되어 기존 토스 redirect 증빙으로 새 구매 권한을 재발급할 수 없습니다.
